# 切点判据与节奏算法

## 一、词级重复与空档（最高优先级判据）

### 1.0 为什么必须落到词

转写分段是 2-4 秒一块。块内的重复词、块间的词缝空档，在段级数据里完全隐形。
用户能听出来的「这词说了三遍」，段级表上看不出来。

**所以：所有切点判断以字/词边界为准，不以句为准。**

工具：`scripts/word_audit.py`（whisper `word_timestamps=True` + ffmpeg `silencedetect`）

### 1.1 重复的四种形态

| 形态 | 实例 | 处理 |
| --- | --- | --- |
| 结巴式并置 | 「但是，但是这盘，但是这盘大地色眼影」 | 只留最后一次完整表述，前面全删 |
| 半句 + 完整重说 | 「不是那种很」停 0.4s →「不是那种很浮夸很劣质的闪片」 | 删半句，接完整句 |
| 孤立残词 + 重说 | 0-0.92s 一声「踩过」→ 1.18s「踩过无数雷之后」 | 从重说句起点起剪 |
| 整段复述 | 同一内容在片中说了两遍，间隔 >2s | 不算结巴，按内容取舍，不在词级处理 |

判据线：**间隔 ≤2.0 秒** 才算结巴式重复。

间隔更远的同词复用（如两处都提到「闪片」）是正常表达，不删——误删会把两个不同卖点压成一句。

### 1.2 先找「更干净的那一遍」，再谈剪

**这是本节最重要的一条。优先整段替换，不要在前一处打补丁。**

实例：26.5-29.6s 是「但是，但是这盘，但是这盘大地色眼影」，而 35.7-38.9s 有同一意思**一次性说完**的干净表述。用后者换掉前者，一个动作同时消掉重复、啰嗦和两处词缝，比逐词剪干净得多，也更不像剪过的。

动手前先全片搜一遍：**同一个意思有没有更完整的一遍？** 有就换，没有才逐词修。

### 1.3 删哪一次

默认**删前留后**（人重说第二遍通常更顺）。
例外：后一次被截断、明显更差、或后一次夹在别的句子中间 → 删后留前。

### 1.4 空档（词缝）

**阈值必须以 ffmpeg 实测静音为准，不能用 whisper 词边界差。**

词边界自带前后留白，实测词缝比真实静音大约多 **0.4 秒**（实证：词缝 0.78s ↔ 真实静音 0.32s）。用词边界直接判断，会把人声呼吸标成「空档」，越剪越紧、最后变机关枪。

| 实测静音 | 处理 |
| --- | --- |
| ≥1.5s | 卡壳或走神，压到 0.30s 以下 |
| 0.8-1.5s | 句间停顿，压到 0.30s |
| 0.45-0.8s | 句内词缝过长，压到 0.18s（两侧各 0.09s） |
| 0.30-0.45s | 正常呼吸，**不动** |
| <0.30s | 不动 |

句子边界保留 0.15s，句内 0.13s（**v3 定版**：11月17日/18日(1) 用户两轮反馈
"停顿有点长"——默认档从 0.30s 收紧到 0.15s，用户确认后可再调）。全压成 0 = 机关枪 + 暴露机器剪。

### 1.4b 停顿区表情体检（必做，前置到决策单之前）

**为什么存在**：口播博主常在停顿时做小表情（撇眼、闭眼、下瞟、低头），三次交付
（11月13日撇嘴×5轮、11月17日撇眼、11月18日(1)撇眼）都是渲染后用户才指出、返工。
根因有二，都是时间轴上看不见的：
1. **ASR 词尾 padding 可达 0.6s+**（实测「蝶」语音 35.56 收尾，whisper 标 36.20）——
   按词边界切，语音后的表情起始帧全留在成片里；
2. 表情动作在段级/词级转写里**零可见**，只有看帧才能发现。

**流程（每个实测停顿都跑，不挑大小）**：

```
python scripts/pause_expression_scan.py --input 素材.mp4 --out 01_工作区/xxx/perception
```

脚本自动完成：RMS 实测语音真实起止（≥-38dB）→ 停顿窗口 ±0.8s 逐帧抽帧 →
人脸+眼部级联检测闭眼帧 → 区分**表情动作（>0.15s，必须删）**与**自然眨眼（≤0.15s，正常不删）**
→ 异常帧自动拼网格 → `pause_expression_report.md` 给出建议切点。

三条硬规则：
1. **切点两侧必须是睁眼帧**：入点 = 表情起始前最后睁眼帧（−0.04s），出点 = 表情结束
   后首个睁眼帧（+0.04s）。表情常起于语音收尾瞬间（如「蝶」35.56 收尾、35.65 闭眼），
   切在 ASR 词尾必然带进闭眼帧。
2. **扫描结果直接进决策单**：每个停顿标注「表情动作 N 处/仅眨眼/干净」+ 拟用切点，
   用户过闸门时一次确认，不留到渲染后返工（★一次性过的关键）。
3. **渲染后接缝逐帧复检必做**（`select='between(t,...)'` 抽接缝 ±0.3s 全帧）：
   帧边界裁剪可能让 trim 末帧吃进表情起始帧（11月18日(1) 实测：切 35.62 时
   末帧落在 35.60 睁眼帧才干净）。网格判读为辅助，目检确认才是结论。

### 1.5 切点落点

- 直接取 whisper 字边界（起点=字起点，收口=末字终点）。这个边界本身在辅音之前、韵尾之后，实测不爆音。
- 出现吃字（首字模糊）→ 起点前移 0.04s；出现截韵尾 → 收口后延 0.05s。
- **不额外留白**：多留 0.1s 就是一次听得见的「顿」。

### 1.6 交付前必须回转写复核

剪完把成片重新转写一遍，数关键词出现次数，再看一遍重复与空档。

```
python scripts/verify_cut.py --input 02_成片/xxx.mp4 --out 01_工作区/verify \
       --expect "踩过:1,但是这:1,不是:1"
```

`PASS` 才交付。这一步能抓到耳朵听不出来的残留：本次就是靠它确认三处重复确实只剩一次。

复核也必须带探针。不带探针的复核只会重复「全片解码把结巴修顺」的老毛病，给出一份假的 PASS。

### 1.7 探针的工程细节（不写下来必定重踩）

**窗口宽度有临界值。** 同一段音频，窗口 1.4-1.8s 时 whisper 会把两遍都转出来（「踩过五踩过五」）；放到 2.2s 以上，它判定第一遍是废起头，直接丢掉，只剩「踩过无数雷之后」。差 0.4 秒，结果完全不同。

**但窄窗装不下需要上下文的重复。** 「但是，但是这盘，但是这盘大地色眼影」要 2.4s 以上才成立。所以必须级联：1.8s 先试，抓不到再放 2.9s。

**跨度只受片长限制，不能被锚点截断。** 这是实现上最容易写错的一处：若用锚点的语义终点去 clamp 结束时间，宽窗和窄窗会一样长，级联等于没做。

**锚点用「异常字」而不是「停顿」。** 结巴两遍之间可能只停 0.19 秒，低于任何静音阈值，靠停顿根本框不住。但合并会把那段停顿塞进某个字里，让这个字异常变长（0.66-1.88s 的「无」就是痕迹）。所以锚点取：时长 ≥0.85s 的字，或置信度 <0.6 的字。

**静音段会诱发幻觉。** whisper 在无声区间会编出「点赞订阅转发打赏」这类循环文本，时间戳常常是零长度。过滤两条：落在实测静音区间内的词一律丢弃；语音覆盖率低于 35% 的窗口整体丢弃。

## 二、气口档位（三版差异用）

静音检测阈值：**-33 dB**，最短静音 0.15s 以上才计入。

| 档位 | 句间气口 | 适用 |
| --- | --- | --- |
| 完整版 | 0.8s | 知识讲解、需要消化时间 |
| 紧凑版 | 0.30s（句内 0.18s） | 抖音/视频号主流，节奏推着走 |
| 极紧版 | 0.18s | 强钩子开场段落 |

规则：
- 句间压到档位值，**段间（章节切换处）保留 0.6-1.0s**，否则整片喘不上气
- 单次实测静音超过 1.5s 的，一律压到 0.30s 以下（这是卡壳，不是留白）
- 压气口时切点落在**波形过零点**，避免爆音

不要做的事：把气口全删成 0。

## 三、句级口误判定（词的层面已经处理完，这里看更高一层）

| 类型 | 特征 | 处理 |
| --- | --- | --- |
| 重复起头 | 同一句开头说了两遍 | 删前一次，保后一次 |
| 半句断裂 | 话没说完就换话头 | 删断裂残句，接后半句 |
| 自我纠正 | 「不对」「我重说」「应该是…」 | 删纠正前的旧说法 |
| 语气词堆积 | 连续 2 个以上「那个」「就是」 | 删到只剩 1 个 |
| 长尾拖音 | 句尾「呃——」拖 0.3s 以上 | 剪掉拖音尾巴 |
| 口水音 | 咂嘴、吸气声 | 优先音频修复，不剪画面 |

**关键判断**：单个语气词是口语节奏，删多了变念稿。**只删堆积和拖音。**

## 四、多余画面

抽帧核对（每段取首/中/尾三帧），命中以下即标记删除：

- 找镜头、看提词器、低头看稿
- 长时间无表情静止（>3s 且无语音）
- 手部遮挡面部、人物出画
- 空镜超过 2s 且与所在段落无关
- **片中插入的黑底文字卡**（常见形态：免责声明、平台引导、「素材补充，非广」）——
  用 `blackdetect=d=0.2:pix_th=0.15:pic_th=0.85` 定位（白字卡达不到默认 98% 黑像素阈值，参数必须放宽）
- **平台推广尾卡**（账号号 + 搜索框那张）：发到别的平台算搬运风险点，默认删

注意：**反应镜头和停顿呼吸不要删**。全删成「一字一剪」会很假。

## 四之二、表情动作覆盖（画面问题 ≠ 音频问题）

**优先级决策（v9 定版）——遇到表情/动作先查它落在哪：**
1. **先查 RMS 包络**：动作区间是否落在实测静音空档（≤-33dB）内？
   是 → **直接删段**（音画同步切，段拆两半），口型天然同步、无口型重复风险。
   案例：闭眼 70.40-70.84 落在 70.24-71.16 空档 → 删空档，弃覆盖。
   ⚠️ 删段边界必须**双向核对**：段头前推时，表情尾迹可能藏在段头几帧里
   （案例：撇嘴尾迹藏在段9头 67.71-68.40 的闭唇微垂画面，「新」68.48 才起；
   帧匹配"0泄漏"只验证了已删区间，段头保留区间的表情尾迹要用嘴部/眼部
   裁切逐帧目检确认——缩略网格上"闭唇自然"的判读不可靠）。
   段边界推到下一词起点前 0.06s 左右（嘴已张开发音，衔接口型连续）
2. 动作在语音收音之后（韵尾衰减区）→ **段尾提前**，段尾加 afade 0.05s 防急促。
   案例：撇嘴 65.17+ → 段尾提前（「片」能量核心 65.06-65.16 刚结束即切）。
3. 动作正压在字上且两侧都是语音 → 才用覆盖法（下述）。
   ⚠️ 覆盖源段若含口型（说话画面），观众会看到口型重播/错位
   （v8 踩坑：覆盖源 69.68-70.32 含「不会翻」口型 → "翻车"口型重播）。
   覆盖窗长尽量 ≤0.5s。

**覆盖法细则（v6/v7 踩坑全记录）：**

用户会指出「26 秒撇嘴」「29 秒向下瞟眼」这类**微表情**。处理流程：

1. **时间换算**：用户给的是成片体感时间，通常偏差 ±0.5s。先用 src2out 映射到源时间，
   再以该点为中心前后各抽 1.2s 逐帧排查（0.1s 步进拼图粗查 → 0.067s 步进细查）。
   **动作的真实区间几乎总比用户说的时间靠后**（体感滞后），必须逐帧确认，不能直接信。
2. **裁剪对位**：先抽全帧确认五官位置再裁细部区域。320×568 源的典型人脸：
   眼 y≈190-260、嘴 y≈205-285（x≈85-235）。裁偏一次浪费一轮（本条踩过：取到刘海区）。
3. **判定是否压在语音上**：查词级时间戳。动作区间与发声重叠 → **画面覆盖**（音频不动）；
   落在语句间隙 → 可直接切。
4. **覆盖法 v2（默认，v6 验证）**：覆盖源用**动作前 0.2~0.5s 的真实视频段**
   （人物自然说话的画面，长度 = 动作窗长度），**弃用单帧冻结**：
   - ⚠️ 禁止 `trim 单帧 + tpad clone`：trim 输出单帧后帧率元数据丢失，
     tpad 按帧率算克隆帧数 = 0，覆盖流总长仅 0.04s，够不到覆盖窗 →
     eof_action=pass 全放行，**覆盖完全失效**（v5 踩坑，特写 trim 2s 不受影响）
   - 实现：`trim 源段,setpts=PTS-STARTPTS,画质链,format=yuva420p,
     fade=t=in:st=0:d=D:alpha=1,fade=t=out:st={L-D}:d=D:alpha=1,
     setpts=PTS+pos/TB` + `overlay=enable='between(t,pos,pos+L)':eof_action=pass`
   - 渐变时长 D = min(0.08, L/4)；两端渐入渐出 → 衔接自然，画面是"活的"不卡顿
   - ⚠️ fade out 锚点（黑底 alpha 实测）：**alpha 归零点 ≈ st 本身，不是 st+d**，
     故 fade out 必须 `st=L`（渐变发生在 [L-d, L]、归零于窗尾）；
     若按文档写 st=L-d 会在窗中段提前变透明，原片动作帧透出（v7 踩坑）
   - ⚠️ 覆盖流长度必须 ≥ 覆盖窗长：trim 按帧边界裁剪会吃掉首尾 0~0.05s，
     窗内流尾提前 EOF → eof_action=pass 放行原片动作帧（v6 踩坑）。
     修法：覆盖源段比动作窗长 ≥0.1s + `tpad=stop_mode=clone:stop_duration=L+0.2`
     （多帧流帧率元数据正常，tpad 可靠；禁止单帧 trim 后 tpad）
   - ⚠️ overlay 对齐有约 1 帧滞后（覆盖实际生效比 pos 晚 ~0.037s），
     覆盖窗两端须各留 ≥0.07s 余量（窗起点 = 动作起点 - 0.07）
   - 验证必须用帧匹配自动对齐（抽成片帧 vs 源帧库算 MAD 取最优匹配），
     检查覆盖窗内是否有帧匹配到动作禁区；源帧库范围必须完整覆盖覆盖源段，
     否则会出现假警报
   - **覆盖窗尾端必须延到动作完全恢复之后**（如闭眼 → 完全睁眼后 0.05s），
     否则渐出混合帧会带动作尾迹（v6 首版踩坑：窗尾 70.82 眼未睁完 → 延到 70.88）
   - 覆盖窗起点 = src2out(动作起点)，**不要用区间中点**（否则窗右移，多盖正常画面）
   - 覆盖源段不能含动作起始帧（终点 = 动作窗起点前留 0.02s）
   - 覆盖必须放在**字幕烧录之前**，否则覆盖画面把字幕盖掉
   - 覆盖窗内画面与音频口型轻微不匹配（0.2-0.5s）可接受，观众不逐帧对口型
5. **验证**：覆盖区起、中、尾各抽一帧 + 区外一帧，30fps 密集网格逐帧核对表情正常、
   无动作残留、无冻结卡顿感。

典型案例（11月13日.mp4 v6）：撇嘴 64.88-65.06 压「闪」字 → 64.62-64.84 画面
渐变盖 64.86-65.08；闭眼下瞟 70.40-70.84 压「车」字 → 69.84-70.38 画面
渐变盖 70.34-70.88。



## 五、节奏基准

口播语速参考：**4.5-5.5 字/秒**（中文）。低于 4 字/秒显拖沓，高于 6 字/秒听不清。

节奏检查点：
- 前 3 秒必须出现信息钩子，不能是「大家好我是…」
- 每 15-20 秒需要一个视觉或听觉变化（换机位、上花字、音效点）
- 单镜头停留不超过 8 秒（纯口播可放宽到 15 秒，但需有花字支撑）

## 六、三版差异

| 版本 | 句间气口 | 删减力度 | 典型时长差 |
| --- | --- | --- | --- |
| v1_full | 0.8s | 只删硬错误（口误、废画面） | 基准 |
| v2_tight | 0.30s | 删口误 + 词级重复 + 长空档 | -15%~-35% |
| v3_breath | 0.5s | 删口误，保留完整表达结构 | -5%~-10% |

交付时必须说明三版差多少秒、差在哪几段，让用户能直接选。

**但词级问题三版都要修**——重复词和长空档不属于「风格差异」，属于错误，任何版本都不许留。

## 七、保留理由必须写

cutlist 每一行都要有理由字段。这是审单能通过的前提，也是返工时能追责的依据。

合格的理由（词级）：
`删` — 26.50-29.60s，结巴式重复「但是/但是这盘/但是这盘大地色眼影」三连，改用 35.70-38.90s 一次性说完的干净版

不合格的理由：`删` — 废话
